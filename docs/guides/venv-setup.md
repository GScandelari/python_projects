# Virtual Environments & Package Management

## Why Virtual Environments?

Each project gets its own isolated set of packages. Without venvs:
- Project A needs `requests==2.28`, Project B needs `requests==2.31` → conflict.
- `pip install` without a venv pollutes the global Python installation.

---

## venv (built-in)

```bash
# Create
python -m venv .venv

# Activate
source .venv/bin/activate        # macOS / Linux
.venv\Scripts\activate           # Windows CMD
.venv\Scripts\Activate.ps1       # Windows PowerShell

# Deactivate
deactivate

# Verify which Python is active
which python       # macOS/Linux → .venv/bin/python
where python       # Windows    → .venv\Scripts\python.exe
```

**Naming convention:** `.venv` is widely recognised by editors (VS Code, PyCharm) and is excluded by most `.gitignore` templates.

## pip Essentials

```bash
pip install requests                   # latest version
pip install "requests>=2.28,<3"        # version constraint
pip install requests==2.31.0           # exact version
pip install -r requirements.txt        # from file
pip install -e .                       # editable install (for your own package)

pip uninstall requests
pip list                               # all installed packages
pip show requests                      # details for one package
pip freeze                             # pinned list (for requirements.txt)
pip freeze > requirements.txt          # capture current env
pip install --upgrade requests         # upgrade
pip install --upgrade pip              # upgrade pip itself
```

## requirements.txt

### Two-file pattern (recommended)

**`requirements.in`** — abstract (human-maintained, just direct deps):
```
requests>=2.28
pandas
fastapi
uvicorn[standard]
```

**`requirements.txt`** — pinned (generated, committed to repo):
```
# Generated by pip-compile
annotated-types==0.6.0
anyio==4.3.0
fastapi==0.110.0
...
```

Generate with `pip-compile` (from `pip-tools`):
```bash
pip install pip-tools
pip-compile requirements.in          # generates requirements.txt
pip-sync requirements.txt            # install exactly what's in the file
```

### Simple single-file pattern

```bash
# After installing what you need:
pip freeze > requirements.txt

# Teammate / CI setup:
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

## pyproject.toml (modern standard)

For packages or structured projects, prefer `pyproject.toml` over `requirements.txt`.

```toml
[build-system]
requires = ["setuptools>=68", "wheel"]
build-backend = "setuptools.backends.legacy:build"

[project]
name = "my-project"
version = "0.1.0"
requires-python = ">=3.11"
dependencies = [
    "requests>=2.28",
    "pandas>=2.0",
]

[project.optional-dependencies]
dev = ["pytest", "pytest-cov", "ruff"]
```

```bash
pip install -e ".[dev]"   # install with dev extras
```

## conda (data science alternative)

```bash
# Create env
conda create -n myenv python=3.11

# Activate
conda activate myenv

# Install (conda packages + pip packages)
conda install numpy pandas matplotlib
pip install some-package-not-on-conda

# Export / recreate
conda env export > environment.yml
conda env create -f environment.yml

# List envs
conda env list

# Remove env
conda env remove -n myenv
```

## Quick Setup Checklist

```bash
# 1. Create env
python -m venv .venv

# 2. Activate
source .venv/bin/activate

# 3. Upgrade pip
pip install --upgrade pip

# 4. Install deps
pip install -r requirements.txt

# 5. Verify
python --version
pip list
```
